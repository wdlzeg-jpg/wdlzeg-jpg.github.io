阿里云企业 Web

从新业务搭建到设计系统沉淀

负责开发者社区与阿里云大学相关页面，从新业务入口、信息架构到视觉系统和移动端适配，支持多项目并行交付。

01 / CONTEXT

问题从哪里来

核心问题
当业务快速扩张时，页面设计必须升级为可复用的架构、组件和协作语言。

业务模块扩张时，用统一的信息架构和多端任务逻辑支撑持续交付。

需要同时解决的三件事

01

内容、工具、课程、赛事入口分散

02

认证流程跨页面、跨端且状态复杂

03

新业务快速搭建缺少统一视觉与组件规则

02 / DESIGN RATIONALE

从任务路径到关键判断

  1. 01需求梳理
  2. 02信息架构
  3. 03视觉系统
  4. 04多端适配
  5. 05上线验收
DECISION 01

统一入口

将内容、工具、课程、赛事和社群收敛到可扩展的开发者生态架构。

DECISION 02

连续任务链

把认证组织为购买、报名、考试、领证的完整路径。

DECISION 03

设计资产

沉淀页面结构、组件和视觉规则，支持 PC、H5 与移动端复用。

03 / DESIGN EVIDENCE

让设计判断回到具体界面

开发者社区、阿里云大学及移动端页面能够证明真实交付范围；旧项目指标不外推当前表现。

交付、结果与证据口径
